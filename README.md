# Редактор схем персонажей

Веб-приложение для наглядных схем персонажей: бесконечный холст, карточки, связи-стрелки, изображения и текст. Всё работает **полностью на стороне клиента** — без сервера и базы данных: схема хранится в браузере (IndexedDB) и переносится файлами (PNG / PDF / JSON). Приложение статически экспортируется и публикуется на GitHub Pages как обычный набор HTML/JS-файлов.

- **Языки интерфейса и кода:** русский (UI, комментарии, документация)
- **Репозиторий-назначение:** GitHub Pages, деплой автоматически через GitHub Actions (см. [Публикация](#публикация-на-github-pages))
- **Ориентир дизайна:** единый набор дизайн-токенов из `variables.json`, объявленный в `src/app/variables.css` (история разработки — в `worklog.md`)

---

## Возможности

- **Бесконечный холст** — панорамирование мышью, зум `Alt + колесо` (0.2–3.0), фон-точки, фоновая картинка (плитка / по осям / заливка) с прозрачностью.
- **Карточки персонажей** — имя, форматируемые годы и статус, описание, аватар (кроп 256×256), сворачивание/разворачивание, удаляемый статус и группировка (перетаскиваются вместе).
- **Стрелки** — привязка концов к карточкам (к центру ближайшей грани, с равномерным распределением по грани) или свободные концы; жирные подписи вдоль наклона стрелки; стиль: цвет, сплошная/пунктир, толщина (thin/normal/thick), наконечники (треугольник/линия/нет), концы (both/end/start/none).
- **Изображения** — вставка с автоматическим сжатием в WEBP, ресайз с сохранением пропорций.
- **Текст** — блоки с HTML-форматированием: жирный, курсив, подчёркивание, цвет, списки; рамка повёрнутого текста повторяет его фактическую ширину.
- **Color Picker** — собственная область насыщенности/яркости, hue-слайдер, HEX-поле и пипетка без нативного всплывающего `input[type=color]`.
- **История и горячие клавиши** — undo/redo (`Ctrl+Z` / `Ctrl+Y`), копирование/вставка (`Ctrl+C` / `Ctrl+V`), выбор всех элементов (`Ctrl+A`), группировка (`Ctrl+G` / `Ctrl+Shift+G`) и удаление (`Delete`). На macOS поддерживается `Cmd`.
- **Множественное выделение** — `Shift + клик`, единая обводка, совместное перемещение, копирование, группировка и удаление выбранных элементов.
- **Мобильные жесты** — перетаскивание элементов одним пальцем, дабл-тап или долгое нажатие вместо ПКМ и pinch-to-zoom с панорамированием по центру жеста.
- **Сохранение** — автосохранение в IndexedDB (с debounce) + импорт/экспорт рабочего JSON-файла (портабельность между браузерами и устройствами).
- **Экспорт** — PNG и PDF в двух режимах: *полное описание* (развёрнутые карточки) и *мини* (схема без деталей); скриншот текущего вида.
- **Контекстные меню** — на холсте, карточке, стрелке, изображении, тексте; меню статусов и сохранённых стилей стрелок.

## Технологии

| Слой | Выбор |
|---|---|
| Фреймворк | Next.js 16 (App Router), React 19, TypeScript 5 |
| Стили | Tailwind CSS 4 + единые дизайн-токены в `src/app/variables.css` |
| Состояние | Zustand (`src/lib/editor/store.ts`) |
| Хранилище | IndexedDB через `idb-keyval` |
| Экспорт | `html-to-image` (PNG), `jsPDF` (PDF) |
| Сборка | Bun; статический экспорт `output: "export"` → папка `out/` |

## Быстрый старт

```bash
bun install        # установка зависимостей
bun run dev        # дев-сервер на http://localhost:3000
bun run build      # статическая сборка в out/ (можно открыть локально: bun run start)
bun run lint       # ESLint
bun run check:tokens # аудит цветов, размеров, отступов и CSS-переменных
```

> Все данные пользователя живут в его браузере. Бэкенд отсутствует: `src/app/page.tsx` — единственный маршрут, серверного кода нет.

## Публикация на GitHub Pages

Проект собран как статический экспорт (`output: "export"` в `next.config.ts`), поэтому ему не нужен Node-сервер — на Pages публикуется готовая папка `out/` с HTML/JS-файлами.

### Способ 1. Через веб-версию GitHub (GitHub Actions) — без терминала и GitHub Desktop

Сборку выполняет GitHub Actions (`.github/workflows/deploy-pages.yml`): любой push в ветку `main` автоматически пересобирает сайт и публикует его.

1. Откройте репозиторий на github.com → **Settings → Pages → Build and deployment → Source: «GitHub Actions»** (один раз).
2. Залейте код в ветку `main` (Merge pull request, либо сразу коммит через веб-редактор GitHub).
3. Вкладка **Actions** покажет запуск «Сборка и публикация на GitHub Pages» — через 1–2 минуты после его успеха сайт доступен по адресу `https://<ваш-аккаунт>.github.io/<имя-репо>/`.

Дальше всё обновляется только через браузер: правка файла на github.com → **Commit changes** в `main` → сайт автоматически пересобирается. Ручной запуск без правок — кнопка **Run workflow** на вкладке Actions.

### Способ 2. Вручную скриптом `deploy.sh` (нужны локальные Bun и git)

1. Создайте репозиторий на GitHub (например, `character-schema-editor`) и запушьте код:
   ```bash
   git remote add origin git@github.com:<ваш-аккаунт>/<имя-репо>.git
   git push -u origin main
   ```
2. Соберите и опубликуйте:
   ```bash
   ./deploy.sh <имя-репо>        # или просто ./deploy.sh — имя возьмётся из remote
   ```
   Скрипт сам задаст `NEXT_PUBLIC_BASE_PATH=/<имя-репо>`, выполнит `bun run build` (результат — `out/`), инициализирует в `out/` временную ветку `gh-pages` и запушит её с `--force`.
3. На GitHub: **Settings → Pages → Source: Deploy from a branch → Branch: gh-pages, папка / (root)**.

Через 1–2 минуты сайт будет доступен по адресу `https://<ваш-аккаунт>.github.io/<имя-репо>/`.

**Особые случаи**

- Репозиторий-личная страница `<user>.github.io` — basePath не нужен; и скрипт, и workflow определяют это по суффиксу `.github.io` и собирают с пустым префиксом.
- `.nojekyll` лежит в `public/` и попадает в `out/` — запрещает GitHub обрабатывать Pages через Jekyll (иначе каталог `_next/` будет проигнорирован).
- Все внутренние ссылки и ассеты учитывают `basePath` из `next.config.ts`; при локальной разработке префикс не нужен.
- Изменения кода при способе 2 → повторный `./deploy.sh` (история gh-pages не копится: каждая публикация перезаписывает ветку).

## Модель данных и формат файла

Рабочий файл схемы (экспорт/импорт JSON, `version: 1`) — это `PersistedState`:

```jsonc
{
  "version": 1,
  "title": "Название схемы",
  "elements": [ /* карточки, стрелки, изображения, тексты */ ],
  "order": ["id-1", "id-2"],          // порядок слоёв
  "settings": { "bgColor": "#f2eeeb", "bgFit": "tile", "bgOpacity": 100 },
  "savedStatuses": [ /* { id, text, color } — сохранённые статусы */ ],
  "savedArrowStyles": [ /* сохранённые стили стрелок */ ],
  "view": { "x": 0, "y": 0, "scale": 1 }
}
```

Соглашения, о которых важно помнить при доработках:

- Координаты стрелок (`fromPoint`/`toPoint`) хранятся **относительно** `(x, y)` элемента; привязки к карточкам — по `fromCard`/`toCard` (id).
- Аватары, изображения и фон — **data URL в WEBP** (сжатие при вставке), поэтому JSON-файл самодостаточен.
- `groupId` объединяет элементы в группу (перетаскиваются вместе).
- Мир рисуется transform-ом от центра вьюпорта, а не от угла; не «упрощайте» это обратно.
- Автосохранение пишется в IndexedDB с debounce; при загрузке JSON проходит валидацию в `storage.ts` (мерж с дефолтами).

## Чистка репозитория (что было удалено и почему)

Исходное рабочее пространство было собрано на платформенном шаблоне (fullstack-скаффолд). Поскольку приложение полностью клиентское, при подготовке к GitHub Pages удалено:

| Удалено | Причина |
|---|---|
| `src/app/api/`, `src/lib/db.ts` | Заглушки шаблона (API-роут и Prisma-клиент); ничем не использовались, API-роуты несовместимы со static export |
| `prisma/`, `db/custom.db`, `.env` | Prisma/SQLite не нужны: хранение — IndexedDB в браузере |
| `examples/`, `mini-services/`, `tests/` | Платформенные примеры (websocket), пустые мини-сервисы и скрипты сборки окружения |
| `.zscripts/` | Скрипты платформенной песочницы (dev/build/скриншоты тестов) |
| `upload/`, `download/`, `Caddyfile` | Референсы UI-kit, служебная папка выгрузки, конфиг обратного прокси песочницы |
| Зависимости `prisma`, `@prisma/client`, `next-auth`, `sharp`, `z-ai-web-dev-sdk` | Серверные/платформенные, кодом не используются |

Неиспользуемый shadcn/ui-scaffold и связанные хуки удалены при централизации токенов: они не входили в runtime-граф приложения и содержали собственную независимую тему. В `src/components/ui/` оставлен только реально используемый токенизированный `sonner.tsx`. В `package.json` ещё присутствуют неиспользуемые шаблонные зависимости; удаляйте их отдельно с синхронным обновлением `bun.lock`.

## Заметки для LLM (и новых разработчиков)

- **Точка входа:** `src/app/page.tsx` → `src/components/editor/Editor.tsx`. Единственный маршрут — `/`.
- **Вся бизнес-логика** — в `src/lib/editor/` (без JSX), **вся разметка** — в `src/components/editor/`. Новые действия над схемой добавляйте в `store.ts`, новые типы — в `types.ts`.
- **Дизайн привязан только к токенам** из `src/app/variables.css`, перенесённым из приложенного `variables.json`. Новые статические цвета, размеры, отступы и шрифты нельзя хардкодить; `bun run check:tokens` проверяет это автоматически.
- **Известные нелогичности, которые так задуманы** (не «чинить» без нужды): SVG-слой стрелок 10000×10000 со сдвигом — иначе контент клипался; `reactStrictMode: false` и `typescript.ignoreBuildErrors: true` — унаследованы от шаблона; `trailingSlash: true` — для корректной раздачи статики GitHub Pages.
- **Проверено в браузере** (см. `worklog.md`): меню, карточки, drag, стрелки с привязкой, стили, зум/пан, undo/redo, collapse, статусы, импорт/экспорт JSON, PNG/PDF (full/mini), WEBP-конверсия, мобильный viewport.
- **Перед коммитом:** `bun run lint` + `bun run check:tokens` + `bun run build` (сборка проверяет и prerender маршрута `/`).
- **Деплой:** только через `deploy.sh` (он задаёт `NEXT_PUBLIC_BASE_PATH`; без него локальная сборка собирается с пустым префиксом — для отладки это ок).
